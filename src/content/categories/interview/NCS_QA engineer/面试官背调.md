## 4. 面试风格预判

### 4.1 整体倾向

| 维度 | 预判 | 依据 |
|------|------|------|
| **技术深度** | 🔴 会追问技术细节 | 他本人是实战型，亲自写 Python 自动化代码 |
| **自动化导向** | 🔴 极度重视自动化 | "自动化" 在他履历中出现了 10+ 次 |
| **流程意识** | 🔴 会考察流程思维 | SDLC 缩短 60% 是他最大的成就之一 |
| **数据驱动** | 🟡 会关注量化结果 | 他的成就都有具体数字（60%、50%、80% 等） |
| **培养新人** | 🟢 对新人友好 | 亲自培养了 4 名应届生 |
| **跨部门协作** | 🟡 会考察沟通能力 | 多次强调跨部门协作 |
| **质量左移** | 🟡 会问"你怎么在早期发现缺陷" | 推行版本控制减少缺陷，证明他重视左移 |

### 4.2 最可能问的问题类型（按概率排序）

```
1. 🔴🔴🔴 Python 自动化经验
   → 你写过 Python 脚本吗？具体做了什么？

2. 🔴🔴🔴 API 测试经验
   → 你怎么测试一个 API？怎么设计测试用例？

3. 🔴🔴 测试流程与方法论
   → 你怎么理解 SDLC？你觉得测试应该在什么时候介入？

4. 🔴🔴 缺陷分析与追踪
   → 你发现过一个印象深刻的 Bug 吗？怎么定位的？

5. 🟡🟡 性能/负载测试
   → 你知道性能测试吗？怎么判断系统性能是否达标？

6. 🟡🟡 CI/CD 与自动化集成
   → 你觉得自动化测试应该怎么融入 CI/CD 流水线？

7. 🟡 Docker / Linux
   → 用过 Docker 吗？基本的 Linux 命令？

8. 🟢 Agile / Scrum
   → 你了解 Agile 吗？QA 在 Agile 中的角色是什么？

9. 🟢 职业发展与学习
   → 你未来 1-2 年想学什么？为什么想做 QA？
```

## 5. 面试策略建议

### 5.1 你要重点展示的

| 你的强项 | 怎么跟面试官背景挂钩 |
|---------|------------------|
| **Smart Bakery Python 后端 (FastAPI)** | 面试官本人写 Python API 自动化，你能聊 API 测试、requests、pytest |
| **自动化测试脚本** | 面试官 400 个测试用例——你哪怕写 10 个也是同方向的 |
| **项目全流程思维** | 面试官优化 SDLC——展示你不仅写代码，还理解需求→设计→开发→测试→部署全链路 |
| **学习能力和主动性** | 面试官培养过应届生——他知道新人啥样，你展示自学过 5 个技术栈他会认可 |
| **量化结果** | 面试官用数字说话——你也用数据：800ms 轮询、50 并发、10 个 LoRA 模型 |
| **Docker / Linux 基础** | 面试官用 Docker、Ubuntu——你能聊基础操作就是加分 |

### 5.2 你要避开的坑

| 坑 | 为什么 |
|----|--------|
| **说"Python 只是学校学过"** | 面试官自己写 Python 自动化，会追问你到底会不会 |
| **对测试流程一问三不知** | 面试官 11 年 QA 管理经验，测试基础是他的舒适区 |
| **不说量化结果** | 面试官满屏百分比——你只说"还行"、"不错"会被比下去 |
| **抱怨学校/项目/老师** | 面试官自己就是管理者，招聘的是解决问题的人 |
| **对自动化不以为然** | 在他的语境里，自动化就是 QA 的核心竞争力 |

### 5.3 可以反问他/她的问题

> 面试是双向的，以下问题既展示你的思考深度，也能了解到实际工作环境：

1. *"您从零搭建了 NCS 视频分析业务的 QA 体系，我很好奇——对于 AI/视频分析这类输出不是二元的系统，您怎么定义'测试通过'的标准？"*
   → 展示你做了功课（知道他的背景），也展示了对 AI 测试的思考

2. *"您提到做过 gRPC + Protobuf 的测试——我目前主要接触 REST API，想了解一下微服务架构下的测试和传统 API 测试有什么主要区别？"*
   → 展示学习意愿 + 对新技术的好奇

3. *"您培养过 4 名应届生，从您的经验来看，一个 QA 实习生在前 3 个月最应该掌握的是什么？"*
   → 展示谦虚学习态度 + 对他经验的尊重
